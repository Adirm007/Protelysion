`compileActorInChat(ref, env, rules)` 只应由用户明确的编译动作调用。`env`提供稳定聊天身份、保存聊天、读取最新MVU、Helper API、Web Locks以及显式传输选择；`rules`来自已核对的宿主规则解析。**当前只接受明确已解析为无固有能力的种族，不能将人类或未知种族默认登记为无特性。** 测试中的技术种族只用于测试。

编译与入场是分开的动作。入场仍须经 `assertEntry` 校验资格、来源和完整缓存；编译成功并不自动允许参战。

执行层：`createBattle` → `advanceBattle` → `chooseAction` → `resolveAction` / `interruptAction`。调用方必须提供已核对的角色、减免和动作数据。现已接入独立内容切片的区域、技能/目标菜单与本地存档；正式宿主入场/结算仍未完成。

可参考 `tests/compiler.test.ts`、`tests/compile-chat.test.ts`、`tests/executor.test.ts`，以及联调目录 `scripts/steps/compiler-live.mjs`。测试夹具不进入发布包，也不是生产兜底角色。

## 已确认的失败交接保持不变

`handoffFailure(port, request)`：宿主离场三资源仍补满；HP0只作为局内败退事实交给专用提示词。后续正文/原读者核心负责复活，不强求立即脚本复活。不二次补满已离场成员，不影响未参战主角，不推进时间、不发200FP、不重复扣物品。

聊天结束日志、固定楼层回执与互斥锁防重。此前已通过真实一次性发送、并发/重试和实际刷新测试；刷新后已再次消耗到41HP的角色不会被重补满。失败附加EJS仅在对应的最新失败用户消息后生效，没有自动 `/trigger`。
