- 道具定义纳入角色一次编译；数量不入语义。单技能夹具明确空背包。
- 状态、种族特性、登神能力进入完整编译，不按整个来源类型阻断；缺种族原文规则仍阻断。
- revive 已合法，未知操作测试改用未声明 op。
- 防御、待机、按计划9.3计算的普攻是明确运行命令，不是编译失败的替代能力；未知原能力仍整卡阻断。
- 普通宝箱整层8%，不再每层固定；事件可能需要“选择→遗物选择”两步。

## 后续集中修复（2026-09-19）

- 执行器：处决优先级、死亡召唤物不重复处理、技能封锁与探索时钟保存、原生状态与游戏副本的生命周期区分；退出只清书海临时内容。
- 编译：完整来源/装备/原生状态归属、跨来源 stackGroup；空/缺失/空白种族不得命中全部种族标题，须在模型前阻断。没有默认人类和替代普攻。
- 打包：嵌入宿主正则的 JavaScript 中所有 `{{` 均转义，避免 Tavern 把原文宏当宿主指令执行；打包真实产物并在 VM 中运行，原文运行时字符串仍完整保留。
- 生命周期：同一聊天仅一个规则推进者；Godot加载期间暂停规则；销毁保存；恢复不重付费用，不复制结算。
- 失败交接：局内死亡事实不通过宿主 HP=0 表达。宿主数值已经结算并填满；原核心负责后续复活、时间、FP。游玩时停不能延伸到后续复活阶段；交接只读引用当前原核心的复活规则，不实现另一份时间/FP算法。
- 召唤奖励：明确 `rewardEligible=true` 且实际击败的敌方召唤物可计经验；按已编译模板名称/等级/召唤定位分组。召回、到期、随主人消失不冒充击败，召唤物仍不是宿主收益人。
- 原读者正文补入的真实技能暴露了后续覆盖点：控制免疫按标准 `control` 键跨来源识别，不伪造全精神伤害免疫；原能力传送以个人成功脱离处理，战外立即、战内可延迟，保留此前个人账本，不发当前战斗奖励，不允许回满后重新入场。后续队友全败仍清此前离场者账本。
- 行动时钟：`target_action` 是后续行动结束，`target_ready` 是后续行动开始；`time.delay` 不再把行动次数误当毫秒。第二次本人就绪传送可序列化恢复，菜单冻结不重复计次，死亡不能被传送当复活。
- 开发依赖 lodash 固定到 4.18.1，未使用 `audit fix --force`，当前审计 0 漏洞。生产/验证采用远端 Node 22.17.0；镜像 Node20 仅辅助运行，不作为版本合规证明。
