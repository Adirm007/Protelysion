# 2026-10-28：读者常驻脚本与书海正文交接（本地开发）

本轮已完成本地源码与产物改造，没有推送、发布、修改线上资源或安装到真实酒馆。程序/角色卡版本保持原值；沿用的0.42.1发行标识不表示这些改动已在线发布。

## 实现

- 集成仓已快进更新至 `b30e378`。读者登记为自动正则的 `九十九夜梦 → tsukumo` 核心运行模块，遵循 `start()` / `stop()`；配套核心正文、脚本与轻量规则由同一次受控导入生成。
- 读者菜单、大厅、唱片机运行在一个常驻控制器。消息页只显示来信；新增消息、重绘、编辑与同聊天候选切换不重建播放器。真正换聊天/换核心会清理旧控制器与窗口。
- 常驻控制器在首次生成前准备人格资料，主题、人格、API设置、图库和原有子功能继续复用。旧已知读者正则按ID与匹配结构迁为轻量规则，保留无关规则。
- 读者FP消费与效果统一提交；操作绑定角色、聊天、消息对象和候选，并记录操作回执。书架与费用同一楼层保存；异步生成失败不预扣FP；旧任务不能在另一聊天/候选继续写入。条目模仿源码由原gzip块提取为可维护文件，并加上下文保护。
- 书海窗口按需加载，普通隐藏/复开保留同一iframe、运行时与Godot实例。隐藏时暂停规则、WebAudio、Godot SceneTree及渲染循环。默认窗口给聊天输入框留出空间，可手动全屏。
- `booksea-game`入口与正文标签在读者已加载时成为轻量控制面板，路由到同一个窗口，不再随每条消息创建完整游戏应用。兼容入口仍可独立启动。

## 游戏中发送原消息

1. 在宿主等待的 `GENERATION_AFTER_COMMANDS` 阶段冻结现场，等待队列提交，将原战局保存在旧楼层。摘要包含当前位置、队伍资源、对手、施法/待决动作、互动、附近对象与未结算收益。
2. 原用户消息被宿主追加后，在宿主等待的 `MESSAGE_SENT` 阶段把正文快照、交接extra和消息变量写到这条原消息，并加 `messageId` 归属。保留用户原文，不补发另一条消息，不触发第二次生成。
3. 配套读者EJS校验实际聊天身份、runId、候选及消息归属，再注入断点。普通后续消息不会因MVU继承变量而反复注入旧断点；重抽/重新生成仍能回溯原用户消息。
4. 已在进行的战斗或特殊互动可以自然承接；待结算收益不提前发放，已支付费用与已完成交易不重复执行。
5. 手动、自动两条入口在正文下行、返回游戏、正文离场前统一读取最新 MVU 三资源、药剂余量及 FP；累计消费和结算回执不回退。正文换层后返回会清理原层战局/互动，沿用同一 runId 和已有收益进入对应新层。真正离场的资源恢复沿用原规则。
6. 取消发送可恢复为暂停的游戏现场，下一次发言仍可交接；删楼按旧快照恢复；关闭会话后，旧任务即使遇到A→B→A聊天切换也不能复活。

普通隐藏/复开已经热复用。正文返回游戏会重建 Godot 显示实例，再读取同一远征存档；这不创建新旅程，也不重置楼层、资源、物品或收益。跨聊天楼层继承的权威进度和回执仍有效；messageId 仅防止旧切换摘要在每次普通发言时重播，正文模式和当前层资料仍持续注入。

新增 `mode-continuity.test.ts` 走真实 sessionPort/message-timeline，覆盖正文第1→4层、游戏推进到6层、再次正文后返回，以及背包/FP/回执。`narrative-depth-transition.test.ts` 覆盖原战斗、事件、补给现场切正文并换层后回游戏，避免新层仍挂旧遭遇。

同层返回的处理已按用户确认实现：已有完整、有效助手正文时，当前战斗或互动交给正文，不重弹旧数值遭遇；原地图、位置、资源、长期效果和既有收益保留，不判胜、不发奖、不退已付费用。没有有效正文、仍在生成、失败或取消时保留暂停现场。助手回复按所选候选与宿主流式状态判断；取消后重生成/重抽成功仅解除当前候选的中止标记。`gen_finished` 不是单独的完成依据。

正文期间成长也同步到同一旅程：读取最新等级、五维、有效资源上限，复用数值重算；已有技能动作、支付和使用记录不重建，不增加模型请求。`narrative-host-growth.test.ts` 与 `numeric-rebase.test.ts` 验证新资源不会被旧上限截断，以及状态/已付动作/时钟保留。

提示词逐字复用原有正文承接句，原入口、失败和成功离场模板保持原文；新增现场以结构化数据提供，不再注入自动切换长说明。真实模型能否按断点自然续写仍需实际游玩验证。

## 大小与边界

最终读者常驻模块946,777字节，加载一份；每封轻信84,695字节。原完整实例三资源合计853,149字节，消息视图文本约减少90.1%。这不是总内存或FPS提升比例，也不是重复网络下载节省比例。

书海仍复用既有内容哈希缓存、轻装下载与回执。当前未减少美术/音频体积，也未改变战斗规则时钟、地图画质或模型本身响应速度。没有执行真实酒馆/真实模型验收，不把合成宿主测试冒充玩家存档实测。
