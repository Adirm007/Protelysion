# 《书海》0.23：行走精灵、直接战斗输入、移动端与聊天删楼回退

开发起始：2026-09-22；最终验收：2026-09-23。目标：Adirm007/Protelysion。仅处理《书海》开发工作区及既有发行路径，未接触其他项目或真实玩家存档。

## 本轮六项要求

1. 使用用户提供的 `chibi_sprite_4dir_fixed.png`，裁剪抠图并替换默认行走图；任意队伍在地图只显示一个行走角色。
2. 移除技能确认按钮。桌面支持鼠标、Enter、空格、E；触屏支持重复点选/双击技能或交互键。
3. 移除目标确认按钮与目标文字按钮面板；以选中立绘头顶箭头和缓慢闪烁表示目标，方向键切换，双击或交互/Enter/空格施放。
4. 核实并修正后端物品编译，跳过没有战斗效力的物品。
5. 解决移动端清晰度、嵌入式全屏尺寸和长按文本方向键问题。
6. 远征、解锁起始层和相关交接记录跟随聊天楼层回退，不能被未来缓存或旧页面迟到写入恢复。

## 实现与边界

### 精灵与图像处理

- 原图 848×1239，原行序下/右/左/上，各四帧。
- `16-Godot可玩区域/tools/prepare-player-sprite.py` 用 Pillow 移除边缘连通的洋红背景、去除边缘染色并对齐脚底；保留紫色眼睛等内部颜色，不使用 AI 重绘。
- 运行图 768×1216，单帧192×304，行序下/左/右/上，脚底锚点(96,296)。生成清单记录原图、输出哈希和全部16帧边界。
- Godot 只生成一个地图行走 Sprite3D；不是把队伍裁为一人，参战成员、数值、宿主头像均保留。
- 原图和处理文件只在开发工作区保留；发行只含编译运行资源及来源说明。新图不再归属或冒称 Pipoya 许可。

### 战斗操作

- 保留0.22的顶部整栏技能介绍、底部双列列表。
- 技能页不再有“确认选择”按钮；桌面点击或快捷键直接进入目标选择，触屏首点预览、再次点同一项或交互键激活。
- 目标状态是独立的表现层光标，不因方向键或悬停推进规则、支付费用或保存宿主。
- 箭头根据一次性缓存的立绘透明像素边界定位，不每帧进行像素读回；只给当前目标显示。被选中图像以1.5秒周期缓慢明灭，尊重减少动画偏好。
- 单目标：单击/首点换焦点，双击/再次点选或 Enter、空格、E、交互键施放。
- 手动多目标保留核心合法性和数量限制，点选可标记，键盘 Shift+空格可标记，施放键提交标记；没有另设确认按钮。选择过程不触发宿主结算。

### 物品编译

核查确认旧版已经存在 `背包 → 道具定义 → 编译映射 → item-*运行动作 → 实际数量扣除 → checkpointHost写回` 的完整链路，不是只有前端列表。

旧逻辑会把部分没有战斗效果的消耗品送入通用能力替换；本轮在 `09-实现/src/core/battle-items.ts` 设置前置筛选，非战斗物品不发给模型、不生成替代攻击。常见回复、百分比回复、复活、伤害投掷物、护盾、净化、属性修正、离场物品新增本地可执行规则；复杂条件组合仍由既有完整动作编译器处理，不静默丢弃额外条款。新编译缓存版本0.23.0，不后台自动调用模型。

### 移动端

- 核查默认值为标准画质，旧的 `auto` 也解析为标准；显式保存的手动轻量选择仍保留。
- 标准档原先开启景深：探索默认关闭景深模糊，保持3D比例1.0；战斗背景的柔化仍保留，不模糊敌方立绘和界面。
- 画布按实际舞台尺寸和设备像素比调整，像素比上限2，避免不必要的GPU开销；监听尺寸/画布变更，不逐帧读取宿主布局。
- 原生全屏不可用时，后备方案扩展同源宿主 iframe 链，处理中间祖先的裁切/变换，跟随可视视口和旋转；不移动、导航或重新载入 iframe，退出逐项恢复样式。跨源上层仍受浏览器权限限制，不能承诺越过权限。
- 方向键改为 SVG/样式虚拟摇杆，带死区、指针捕获和160ms步进定时器；无额外绘图或动画循环，抑制长按菜单/文字选取，松手、取消、暂停和退出均停止输入。

### 聊天楼层存档

- `09-实现/src/host/message-timeline.ts`：完整进度存于发生游戏活动的消息元数据 `bookseaCheckpointV1`，消息变量仅带 `bookseaProgressRef`。普通回复无需复制整份地图/角色运行态。
- 聊天变量中的进度只是可重建镜像和轻量索引；角色编译缓存、设置及其他功能变量不随游戏回退被清空。
- 保存绑定当前聊天、消息对象/楼层标识；删除、换楼、同编号新消息都能使旧运行实例失效。守卫只检查轻量身份，不逐帧读取变量或扫描历史。
- 本地缓存必须匹配被保留楼层/继承来源的标识和检查点修订，不能仅凭同一 runId 覆盖旧楼层。
- 结算资源、消耗账本和进度检查点一起写入所属消息，保留原来的防重复奖励/交接规则；旧页面的排队写入在执行前再次检查绑定。
- **旧版没有历史快照**：升级只把当前已提交进度绑定到当前楼层，不把它回填到以前的消息。不伪造过去数据，也不信任无法定位楼层的旧本地缓存。删除首次绑定楼层并退到此前时，不继承被删楼层的高层解锁。
