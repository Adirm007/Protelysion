## 0.5 数值铁律（违反即不通过评审）

1. **所有百分比伤害/夺取一律按最大 HP 计**，禁止"当前 HP 的 x%"。（唯一例外：T29 的"超出半血部分"是按最大 HP 的 50% 线定义的，仍是最大 HP 基准。）
2. 单次百分比效果 **≥15% 最大 HP** 起步，随层级线性增长（t3 15% → t5 25% → t7 35–50%）；每轮持续型 **≥15%/轮**。不足 10% 的百分比数字不允许出现。
3. 属性增减 ≥20% 起步；"每轮 +5%"这种慢增长只在**无上限**且叠加到 ≥100% 时允许。
4. 参照对象是冬之钟/医术师：一个机制要么在 3 轮内改变战局，要么不要。
5. 分配器中每个数值都是 `scale(tier)` 函数，不写死。

## 2. 跨系统改动（0.31.0 第一步）

### 2.1 影响范围：只在本次迷宫内
- 所有对玩家单位的"永久"效果（偷技能、封技能、属性收割、次数扣减、闪避永久降低等）实现为 **`duration.clock:'run'`**（探索/迷宫结束即清）或 `'battle'`。绝不写 `permanent`。
- 在 `run` 结束（迷宫退出/通关/团灭）处调用现有 run 清理：确认 `sourceLocks`、`sealed`、`used`、`charges`、`copy` 产生的授予动作都被清；补一个测试 `run-end-clears-malice.test.ts`。
- 文案统一后缀"（本次迷宫内）"由 UI 层在 `clock==='run'` 时自动加，不写进描述。

### 2.2 玩家技能次数（为 T28/G5/T07 等提供基础）
现状：动作有 `perBattleUses` 字段与 `uses` 效果，但玩家技能几乎全为 0（无限）。方案：
- **不给玩家技能加次数上限**（不改变现有体验）。
- 引入"**技能负载**"概念：`uses spend` 作用在 `perBattleUses=0` 的动作上时，累计到 `used[key]`；执行器判定 `sealed` 优先于 `used`，因此对无限技能"扣次数"无效。改为：`uses mode:'seal'` + `duration`（**封印**）表达"次数被拿走"；`uses mode:'charge'` 给敌人自己的偷来技能加可用次数。
- 于是 T28/G5 的"次数税"改写为"**封印税**"：每次触发封印目标一个技能 N 轮（见 §3/§4 定稿文案）。若日后玩家技能引入 `perBattleUses>0`，`spend` 自动生效，无需再改。
- 需要新增一个执行器小特性：`uses seal` 的 `selection:'used_latest'|'used_random'|'most_used'`（现在 `skill` 只能指定 key 或 `'*'`）。改 `contract.ts` 的 `Uses` 加 `selection?:` 并在 `executor.uses` 里解析（参考 `copy` 的 selection 实现）。**这是唯一需要的契约扩展。**

### 2.3 失控（T01 与 G 系共用）
- 使用已有 `charm` 控制：被魅惑单位阵营临时反转，由怪物 AI 操控，会对原队友使用技能。
- 新增预设状态 `失控`（tags `control:charm`，polarity negative，duration 1–2 轮，`stack:'refresh'`），并在 combat-ai 中给被 charm 的玩家单位一个"优先用带伤害技能打原队友、其次普攻"的行为。
- 无解墙标签：`seals:['control']`。同一怪不得同时拥有"失控"+"沉默全队"两类。
