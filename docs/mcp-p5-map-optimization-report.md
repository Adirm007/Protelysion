# P5 HD-2D 地图模块：验收与 0.25.0 发布记录（2026-09-25）

本文记录三件事：P5 地图模块（`p5-hd2d-2`）的验收结果、它如何移植进正式项目，以及 0.25.0 的发布情况。

路径约定：
- `09-实现/`、`16-Godot可玩区域/`、`19-正式随机地图/` 指开发工作区。
- 发行仓库只包含 `site/`、导入入口、许可和交付文档。
- 计划见 `docs/mcp-p5-map-optimization-plan.md`。

## 1. 范围

**做了：**
- 优化 P5 随机地图，覆盖规则层、渲染内核、Godot 表现层和 48 主题建筑。
- 新增三种地图加载过场。
- 对完整模块做审计。
- 移植进正式项目，发布 0.25.0（仓库和 GitHub Pages）。

**没做：**
- 不更新本机酒馆，不运行 `install-entry.mjs`，不改宿主正则。
- 不清聊天、角色或存档，不调用真实模型。
- 战斗、掉落、结算和补给员规则保持原样。

## 2. 地图模块

**版本：**

| 组件 | 版本 |
|---|---|
| 布局 | `p5-hd2d-2` |
| 建筑 | `hd2d-architecture-3` |
| 渲染内核 | `p5-kernel-1` |
| 楼层包 | `p5-pack-1` |

**规则层 `generateFloor()`**
- 输出可存档的楼层布局，包括通行格与高度、楼梯、POI、建筑、室内和布景。
- 单层平均 9.0 ms。

**建筑与主题**
- 13 种建筑语言：中世纪、地中海、边疆、东方、维多利亚、工业、都市、部落、北欧、有机、奥术、古典、童话。
- 每个主题有自己的常规建筑组合、装饰词汇、墙色变化和标志性建筑。标志性建筑例如：
  - 钟楼、宝塔、风车、水车磨坊、灯塔
  - 木构教堂、天文台、书塔
  - 马戏帐篷与旋转木马、剧院吊景塔
- 有外景的主题共 32 个。抽样 4 个种子时，每个主题至少出现 4 种建筑类型，其中 31 个主题出现了标志性建筑。

**渲染内核 `buildFloorMesh()`**
- 在浏览器内按布局确定性生成：
  - 网格，按 16 m 分块、按材质层合并；
  - 程序化像素材质；
  - 烘焙 AO、暖色灯光和生活痕迹。
- 通过 `BookseaPlay.floorPack(id, quality)` 以 GLB 加纹理数组交给 Godot 的 `godot/maps/p5_scene.gd` 原生导入。
- 渲染数据不写入存档。存档中的区域 JSON 中位数为 19.5 KB，P4 时约为 39.5 KB。

**画面**
- 参照《八方旅人2》的 HD-2D 画面：
  - 多层台地、楼梯、挡墙；
  - 倒角与凹窗、瓦垄屋顶、门口道具簇；
  - 暖冷光、移轴景深、泛光与暗角；
  - 室内剖切。
- 画面是否达标由用户最终判定。自动化测试只保证规则和预算，不代表美术验收。

**异常层**
- 默认 2% 概率，独立判定。
- 共 4 类：后室、泳池房、拼贴、错位套印。
- 每层至少 8 个闯入物，并且保持连通。

## 3. 地图加载过场

实现在 `09-实现/src/ui/loading-veil.ts`，共三种：

| 过场 | 画面 |
|---|---|
| 图书馆 | 翻页、飞书、烛光与尘埃 |
| 童话仙境 | 立体书城堡、怀表、兔子与星光 |
| 提线剧场 | 幕布、聚光与提线人偶 |

**选择规则**
- 按主题亲和选择过场，例如 T15、T22 用图书馆，T04、T12 用童话，T48、T34 用剧场。
- 其余主题按楼层 ID 哈希选择，同一楼层每次选到的过场相同。

**显示时机**
- 首次进入迷宫、每次跨层、渲染器重新连接时显示。
- `runtime` 发出新楼层后立即显示。Godot 的 `game.gd` 收到新楼层后延后两帧再构建，让过场先画出来，构建完成并回执后才淡出。
- 最短显示 1.2 s，淡出 0.4 s，避免闪烁。超过 20 s 时追加“请再稍候”的提示。

**动画与无障碍**
- 动画只使用 transform 和 opacity，在合成线程运行，主线程建场时仍然流畅。
- 遵循系统的“减少动态效果”设置。

## 4. 审计发现与修复

1. **敌群候选点堵死通道（已修复）**
   - 问题：未击败的敌群会占住唯一通路。抽样中有 138/4663 个互动点只能穿过敌群到达，旧测试 `expedition.test.ts` 因此寻路失败。
   - 修复：`maps/generator.ts` 放置敌群时避开咽喉格，最多重试 32 次，并在布景完成后复核。`maps/validate.ts` 新增规则 `encounter-bypass`。
   - 结果：批量 576 层中堵塞为 0，`expedition.test.ts` 全部通过。
2. **拼贴异常层材质层数**：86 层，超过常规层 64 层的预算。已在 UV2（A + 128·B）编码范围内记录上限为 ≤127，测试中单独断言。
3. **旧存档**：P4 地图存档按既定策略拒绝，提示新开远征，不迁移。角色、背包和聊天不受影响。
4. **楼层包桥接**：只对当前楼层返回数据，ID 不符或运行时已释放时返回 null。按“楼层|指纹|画质”缓存最近 2 份，不进存档。
5. **Godot 延后构建的边界**：只有楼层的第一帧携带布局。`game.gd` 会缓存最近一次的布局，所以回到标题再继续同一层时，仍能正常构建。

## 7. 性能测试说明（给测试人员）

**打开与操作**
1. 打开 https://adirm007.github.io/Protelysion/ ，完成首次资源下载，然后新开远征。
2. 按 F12 打开控制台，输入 `BookseaPlay.receipt().renderer`。
3. 在菜单的“设置”里切换“标准画质”和“轻量画质”，对比两档数据。下楼后读取新楼层的数值。

**读取的字段**

| 字段 | 含义 |
|---|---|
| `kernelMs` | 内核生成网格与材质的毫秒数 |
| `packMs` | 取楼层包的总耗时 |
| `importMs` | Godot 导入 GLB 的耗时 |
| `buildMs` | 建场总耗时 |
| `triangles`、`chunks`、`textureLayers` | 场景规模 |
| `frameMsP50`、`frameMsP95` | 最近 240 帧的帧时间 |
| `quality`、`renderScale`、`dofEnabled` 等 | 画质档位与后期开关 |
| `BookseaPlay.loading()` | 当前是否在显示加载过场 |

## 8. 边界与待判定

- **美术**：画面接近《八方旅人2》的程度由用户判定。
- **真机**：手机真机发热和长时间帧率没有测过，浏览器验收只在桌面 Edge 上进行，手机为视口模拟。
- **耗时**：建场耗时受 CPU 影响，内核在主线程运行，期间由加载过场遮挡。
