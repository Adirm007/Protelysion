# 遗物与事件系统重制：99 条设计表（0.36 计划稿）

## 0. 总则

- **作用范围**：遗物默认只作用于持有者；涉及全队共享资源与条件（FP、宝箱、遇敌、素材掉率、楼层规则、来访者）的默认全队。表中 `范围` 列写明。
- **槽位**：每名角色可持有遗物数 = 其生命层级（Lv1–4 为 1，Lv5–8 为 2 …… Lv21–24 为 6，Lv25 为 7）。超出上限时拾取界面只允许"替换"或"放弃"。
- **转移 / 丢弃**：探索中可把遗物转给同行队友或丢弃；带 `[不可转移]` / `[不可丢弃]` 词条的除外。
- **叠加**：同名遗物不可重复持有（一人一件）；不同持有者各自生效。
- **数值语言**：`×` 为乘算修正，`+%` 为加算百分点；"攻击力"= 全部伤害通道倍率，"速度"= 行动条速度，"防御"= 三通道减伤。
- **战斗计数**：每层从 0 起计"本层第 N 场战斗"，换层重置；"每战第一个……"以该场战斗内该角色首次满足条件的动作为准。
- **事件**：只能通过补给员接触触发（补给员菜单见 §2.5）；表中所有“支付 FP”都是事件自身的代价；每条事件给出选项与结果，风险类结果按权重公开掷骰；"待结算 FP" 指本次迷宫尚未撤离结算的 FP。
- 命中 / 落空与暴击系统**引擎已有**（`hitChance/evade`、`crit/critMultiplier/crit_taken`），R13/R14 直接挂修正。

编号：R = 遗物（60 条），E = 事件（39 条），合计 99。★ 为用户给出的原条目（可直接用）。

## 3. 实施要点（供 0.36 开发）

- **数据层**：`relics.ts` 重写为声明式表（id、name、rarity、scope、tags[transfer/drop]、effect DSL），事件同理；效果由"遗物执行器"翻译成现有契约效果（`modify` / `rule` / `apply_status` / 触发器）或"跑段钩子"（FP、宝箱率、遇敌、掉率、层规则）。
- **跑段钩子**：`State` 新增 `layerFights`（本层战斗计数）、`relicFlags`（如 R03 门槛、R15 借据、R25/R49 累计）、`fpModifiers`；`battleDrops` / `awardVictory` / `chestSpawns` / `makeRegion` / `newDepth` / `tickExploration` 读取。
- **槽位与转移**：`PartyMember.relics[]`，容量 = `lifeTierOf(level)`；探索菜单新增"转移 / 丢弃"，受词条约束。
- **群敌（R12）**：`makeRegion` 时把普通遭遇 foes 扩到 3–4 个同主题随机 N 系。
- **命中 / 暴击（R13/R14）**：R13 = 全场 `guaranteed_hit '*'` 规则 + `evade` 归零；R14 = 修正 `crit +1`、`crit_taken ×2`（已存在）。
- **「?」相关（R08/R59/E23/杀害）**：读 `STRAY_STEP_MS` 与 `STRAY_SPAWN_CHANCE` 的跑段覆写；`State.strayGuaranteedOnce` 由「杀害」置位、下一次个位 9 楼层消费。
- **补给员**：`supplier.ts` 菜单改为 事件 / 长椅 / 商店 / 杀害；商店读写 `s.inventory`（现有药水背包），药剂在战斗中作为 `category:'item'` 指令执行。
- **测试**：每条至少一项行为测试；99 条全部通过契约校验；奇偶场 / 层计数 / 传送边界 / 槽位上限 / 转移词条各有专项。
